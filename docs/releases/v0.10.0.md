# Motoro v0.10.0

This release covers capability resolution and LLM request construction.
ASAREE integration is a separate follow-up.

- Unknown models now send `reasoning_effort="medium"` and omit temperature.
- `ModelConfig.resolved_capabilities` and `PartialModelConfig.resolved_capabilities`
  accept validated `ModelCapabilities` metadata, overriding registry lookup.
  Structured, text, native tool, and tool-selection requests share this decision.
- Effort-only models use configured effort or the resolved default effort.
- Unsupported effort raises `UnsupportedEffortError` before a request, without
  transport retries or fallback execution. Supported levels come from the
  resolved metadata, including provider-specific strings.
- `TEMPERATURE_ONLY_CAPABILITIES` provides an explicit custom-model override.
  Existing catalog controls remain unchanged.

Compatibility: custom or unregistered temperature-only models must supply an
explicit override. Effort-only requests previously omitted unset effort; they
now send the metadata default. Configured effort was previously ignored for
temperature-only models and is now rejected. Capability metadata is validated
for consistent effort levels/defaults and rejects unknown fields.

See [the public API and ASAREE example](../../README.md#model-capabilities).
