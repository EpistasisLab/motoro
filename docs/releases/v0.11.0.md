# Motoro v0.11.0

Runs can carry their own complete agent configuration, allowing concurrent
variants of one shared agent without changing its row.

- `create_run(config_snapshot=...)` accepts a dict or `AgentUpdate`. It validates
  agent settings and pattern parameters, captures omitted fields at creation,
  and stores the complete configuration in the existing JSONB column. No schema
  migration is required.
- Execution resolves prompt, goal, name/description, model, patterns, skills,
  output contract and memory through `effective_agent_config(run)`. Explicit
  nulls clear optional settings. Budget and duration values are available through
  the same helper for the product's existing enforcement.
- Model overrides continue to shallow-merge on top. A pinned pattern wins over
  legacy pattern overrides. Calls without a snapshot read current agent settings
  at execution and record what they used for audit and subsequent executions.
- ReAct writes `reason_act_state` into `run_metadata`, preserving caller
  metadata and leaving pattern input unchanged. Consumers of the old telemetry
  location must read the new location.
- Snapshot serialization excludes model API keys, including fallback keys.
  Skill IDs are pinned; skill bodies still resolve at execution. Tools remain
  per execution.

The existing `config_snapshot` field originated with the SRPA runtime in commit
`375911a`, documented as the resolved configuration captured at dispatch. This
release implements that intent without adding another configuration column.

See [the public API example](../../README.md#per-run-agent-configuration).
